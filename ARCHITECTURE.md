# София — ИИ-помощник на заводе

> Подробное описание стека, архитектуры и внутреннего устройства проекта.

---

## 1. Обзор проекта

**София** — RAG-бот (Retrieval-Augmented Generation) для ответа на вопросы по внутренней производственной документации завода Газпром Нефть.

**Что умеет:**
- Отвечает на вопросы по документам (PDF, DOCX, TXT, MD, XLSX) на русском языке
- Показывает источники ответа (файл, страница, фрагмент)
- Показывает изображения из документов (схемы, чертежи, фото)
- Распознаёт голосовые вопросы (STT)
- Проводит адаптацию новых сотрудников (онбординг-чек-лист из 9 шагов)
- Управление пользователями, документами и настройками через веб-интерфейс

## 4. Поток обработки вопроса (RAG)

Когда пользователь задаёт вопрос, происходит следующее:

### Шаг 1. Ретривер (поиск по векторам)

```python
# rag.py — RagEngine.ask()
docs = self.retriever.invoke(question)
```

- Вопрос преобразуется в вектор с помощью `OllamaEmbeddings` (qwen3-embedding-4b)
- ChromaDB находит `top_k` (5) наиболее похожих фрагментов методом MMR (Maximal Marginal Relevance)
- MMR выбирает не только релевантные, но и разнообразные фрагменты (fetch_k=15 кандидатов)

### Шаг 2. Проверка релевантности

```python
scored = self.vectorstore.similarity_search_with_relevance_scores(question, k=top_k)
max_score = scored[0][1]
if max_score < self.cfg.relevance_threshold:  # -2.0
    return "Информация не найдена"
```

- Если максимальный скор релевантности ниже порога → ответ «Информация не найдена»
- Это защищает от «галлюцинаций» когда LLM пытается ответить на нерелевантный вопрос

### Шаг 3. Формирование контекста

```python
context = format_docs(docs)
# Результат:
# [файл_1.pdf, стр. 5]
# Текст фрагмента 1...
# ---
# [файл_2.pdf, стр. 12]
# Текст фрагмента 2...
```

### Шаг 4. Запрос к LLM

```python
prompt = self.prompt.invoke({"context": context, "question": question})
answer = self.llm.invoke(prompt).content
```

- Системный промпт (`RAG_SYSTEM_PROMPT`) задаёт роль: «Ты — ИИ-помощник специалиста»
- LLM получает контекст + вопрос и генерирует ответ
- Модель: `google/gemini-2.5-flash-lite` через Polza.ai (OpenAI-совместимый API)
- Temperature: 0.0 (максимальная детерминированность)

### Шаг 5. Пост-обработка

- Проверка: если LLM ответил «Информация не найдена» → финальный ответ «не найдено»
- Фильтрация источников: только страницы, на которые есть ссылки в ответе
- Отбор изображений: relevance scoring + фильтрация шума (логотипы, фоны)

## 6. Фильтрация изображений

RAG-движок показывает изображения только если они релевантны ответу:

### Алгоритм

1. **Шум-фильтр** (`NOISE_KEYWORDS`): отсеивает логотипы, колонтитулы, водяные знаки, рамки, подложки
2. **Длина описания**: описание < 15 символов → пропуск
3. **Overlap с ответом**: ≥2 слов пересечения с ответом LLM → показать
4. **Технический тип**: если описание содержит «схема», «диаграмма», «таблица» и ≥1 слово пересечения → показать
5. **Визуальные триггеры**: если ответ LLM содержит «схема», «чертёж», «таблица» и картинка >20KB → показать даже без описания
6. **Дедупликация**: по MD5-хешу содержимого

## 7. Онбординг (адаптация)

### Структура

Файл `data/documents/onboarding_checklist.txt` содержит 9 шагов:

| Шаг | Название | Содержание |
|---|---|---|
| 1 | Знакомство с Софией | Приветствие, возможности |
| 2 | Команды и возможности | Список всех команд |
| 3 | Источники информации | Категории документов |
| 4 | Практика: поиск по инструкции | Задание на поиск |
| 5 | Практика: настройка станка | Работа с SOP |
| 6 | Практика: нештатная ситуация | Экстренная процедура |
| 7 | Закрепление | Проверка усвоения |
| 8 | Самостоятельная работа | Первый реальный вопрос |
| 9 | Завершение | Итог, шпаргалка |

### Механика

- `OnboardingManager` парсит чек-лист и хранит шаги
- Навигация: «далее» → следующий шаг, «назад» → предыдущий
- LLM-наставник отвечает на вопросы сотрудника в контексте текущего шага
- В левой панели отображается прогресс-бар и текущий шаг

## 14. Известные особенности

### Отрицательные скоры релевантности

Модель `qwen3-embedding-4b` возвращает отрицательные значения cosine similarity. Поэтому `relevance_threshold` установлен в `-2.0` (вместо типичного `0.35`). Это нормально — порог просто означает «показать ответ если скор выше -2.0».

### ChromaDB readonly error

При переиндексации используется `collection.delete()` внутри открытой сессии Chroma вместо `shutil.rmtree`. Это безопаснее и не ломает singleton-клиент.

### RAG не падает при пустой базе

`RagEngine.__init__` вызывает `_try_load_vectorstore()`. Если `chroma_db/` не существует — `vectorstore = None`, `ask()` возвращает «Информация не найдена», сервер работает. После индексации база подгружается автоматически.

### PDF-парсинг

`PyMuPDFLoader` извлекает текст и изображения. Если PDF содержит отсканированные страницы (изображения вместо текста) — OCR не подключён, текст не извлекается.
